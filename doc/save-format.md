# 黑神话：悟空 存档格式

基于 Steam build 21393610，以及 2024 年 10–11 月的存档。改过的存档已在游戏中实际读档验证。

## 文件

存档目录：`<游戏目录>/b1/Saved/SaveGames/<Steam ID>/`

| 文件 | 内容 |
| --- | --- |
| `ArchiveSaveFile.<N>.sav` | 第 N 个存档位（最多 10 个） |
| `ShareArchiveSaveFile.sav` | 账号级共享数据，封装方式与存档相同 |
| `UserSettingSaveGame.sav` | 游戏设置，明文 protobuf |

游戏自己会把存档滚动备份到 `b1/Saved/SaveGamesBackup/{01RealtimeBackup,02HourlyBackup,03DailyBackup}`。

## 封装

整个文件是一个 protobuf 消息：

| 字段 | 内容 |
| --- | --- |
| `1` | 文件头（protobuf） |
| `2` | 存档数据：明文 protobuf 循环异或 8 字节密钥 `7b5cda913efcda37`，没有压缩，约 2.7 MB |

文件头字段：

| 字段 | 内容 |
| --- | --- |
| `1` | 校验值（`ShareArchiveSaveFile.sav` 里在字段 `2`） |
| `4` | 保存次数 |
| `5` | 保存时间（Unix 时间戳） |
| `6` | 首次保存时间 |
| `9`、`13` | UUID（`13` 与 `ShareArchiveSaveFile.sav` 共用） |
| `12` | Steam ID |

### 校验值

```
md5(加密后的存档数据 + UTF-8 "lhx2tkh6lj1wj8jmrgs3k1xb2brusehx")，小写十六进制
```

游戏读档时会核对它，对不上就提示校验错误、拒绝读取。这个算法已在 28 份游戏自带备份、当前存档和两份 `ShareArchiveSaveFile.sav` 上全部验证通过。编辑器每次保存都会重新计算，也能单独修复校验值不对的存档。

来源：游戏 C# 代码 `b1.BGW_GameArchiveMgr::CalcByteArrayMD5(data, salt)`。盐值和异或密钥都在这个类的静态构造函数里，密钥是 int64 常量 `4024806562674138235`（小端序即 `7b5cda913efcda37`）。

## 字段

解密后的根消息叫 `FUStBEDArchivesData`。存档里没有字段名，下面的路径是 protobuf 字段号，含义是对比同一周目 29 份不同时间的存档推断出来的。

写法说明：`a.b{1:x}.c` 表示在重复字段 `b` 里找子字段 `1` 等于 `x` 的那一项，再取它的字段 `c`。

| 数据 | 字段路径 | 说明 |
| --- | --- | --- |
| 灵韵 | `1.1.2.1{1:1}.2` | 货币条目，类型 1；在各存档间时多时少（100141 → 547 → 1696） |
| 累计死亡次数 | `6.1.5.1` | 在所有存档里都等于各章死亡次数之和 |
| 各章死亡次数 | `6.1.5.2{1:章节}.2` | 章节编号 10、20 … 60 |
| 游戏时长（秒） | `1.2.1.1.2`、`1.2.1.2.2` | float32，实时计数 |
| 游戏时长（秒） | `6.2.2.1`、`6.2.2.2` | 整数副本，比 float 值略落后 |
| 各地图时长 | `1.2.1.3[{1:地图, 2:秒}]` | float32 |
| 等级 | `1.1.1.4` | |
| 到达的最高章节 | `1.1.11.1` | 章节编号 ×10 |

只知道结构、含义还没确认的：

| 字段路径 | 推测 |
| --- | --- |
| `1.1.2.2[{1:编号, 2:数量}]` | 背包道具 |
| `1.1.3.2.7` / `1.1.3.2.1` | 累计经验 / 当前经验 |
| `6.1.1[{1:首领编号, 2:{1:时间戳, 2:次数}}]` | 首领计数（各项加起来 290，不等于死亡次数） |
| `6.2.1.6[{1:"UGuid.HFS.JCZL", 2:次数}]` | 按实体 GUID 记录的计数 |

章节名称：10 火照黑云、20 风起黄昏、30 夜生白露、40 曲度紫鸳、50 日落红尘、60 未竟。

## 编辑方式

不能把整个存档重新序列化。编辑器只替换目标字段的字节，并重新编码它上层各级消息的长度前缀，其他字节保持游戏写入时的原样。文件头除校验值外原样保留。

## 游戏代码在哪里

游戏逻辑是 C#（Mono）。69 个托管程序集以完整 PE 文件的形式直接嵌在 `b1/Binaries/Win64/b1-Win64-Shipping.exe` 里，不在 pak 中。其中 `BtlSvr.Main`（37 MB）包含 `b1.*` 游戏代码，另外还有 `GSE.*`、`Google.Protobuf` 等。

提取方法：在 exe 里搜索 `MZ 90 00`，检查 CLR 头，按节表算出文件大小后切出来。

查看方法：用 Windows PowerShell 5.1 自带的 .NET 反射（仅反射加载，不执行代码），通过 `Module.ResolveString` / `ResolveMember` 和 `MethodBody.GetILAsByteArray()` 读 IL，不需要第三方工具。protobuf 消息类里有真实的字段名，以后要加字段可以从这里查。

pak 的情况：
- 版本 11，footer 在版本号后多了 2 个字节。
- 索引用 AES-256 ECB 加密，密钥 `A896068444F496956900542A215367688B49B19C2537FCD2743D8585BA1EB128`。
- 压缩方式 Oodle。
- 里面没有托管代码。
